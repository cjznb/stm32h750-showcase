## 1. 渲染：42 → 52 fps，且结论是"关掉一个加速器"

### 1.1 问题与基线

| 项 | 基线状态 |
|---|---|
| 上屏方式 | 2 个 60 行 PARTIAL 缓冲 + **MDMA 全屏拷贝** |
| Empty screen flush | **≈12 ms**（拷 768 KB） |
| 平均帧率 | **42 fps / 21 ms** |
| 慢场景 | 被阻塞渲染 + 同步等刷新锁死 |

### 1.2 四步改造（每步都有量化）

| 步骤 | 做法 | 量化结果 |
|---|---|---|
| ① 换掉上屏 | 三缓冲 + LVGL `DIRECT` + **CFBAR 影子寄存器在垂直消隐期换页**，删除 MDMA 拷贝 | flush **≈12 ms → 0**；Empty **46 → 62 fps**（面板刷新率上限） |
| ② 异步门控 | 只有"下一块正被扫描"才等 vblank，否则立即放行 | 渲染慢于帧周期时**不再被刷新率锁死** |
| ③ 抢回 CPU | 高频 ISR + 渲染热链进 **ITCM**；触摸改 **TIM7 + I2C DMA** 后台采样 | 帧耗时 **−29%**（21→15 ms）；GUI CPU **62%→48%** |
| ④ 关掉 DMA2D | 判别实验后整体弃用；把 AXI 堆改可缓存 | 平均 **47 → 52 fps**、**11 ms**；`opa_layer` 场景 **10 → 42 fps** |

### 1.3 被否证的方案（面试常被问到）

| 假设 | 怎么否掉的 |
|---|---|
| "CPU 忙是因为 DVFS 自锁" | 用户两条硬事实：QSPI 速率固定不随 CPU 变；同平台历史 RGB565 能跑 52 fps ⇒ 直接因素是**像素格式/渲染负载**，不是频率 |
| "等锁/放行有阻塞" | 实测等锁 `wait_us ≤ 14 µs`、vblank 放行 `gate_us = 0` ⇒ 不是锁的问题 |
| "DMA2D 能救" | 单变量实验：关掉后帧率**一点没变** ⇒ 零收益；且关掉后显示损坏与崩溃消失 ⇒ 它才是问题源 |

## 2. 撕裂：一个现象、两个机理

| | 现象 B（水平位移撕裂） | 现象 A（成串随机撕裂 + 时间跳 26:10） |
|---|---|---|
| 根因 | **SDRAM 刷新计数写死 1855**，DVFS 改 HCLK ⇒ SDCLK 变 ⇒ 实际刷新间隔 **58 µs**（要求 ≤15.6 µs），整阵 ≈238 ms（要求 64 ms） | 低 SDCLK 大摆幅下 **FMC 读采样相位失配**（+ APB4/RTC 瞬态读回非法小时值） |
| 修法 | `COUNT = floor(HCLK×125/16e6) − 20`，注册调频 AFTER 回调重编程 | 禁最深省电档（不进 HSI）⇒ SDCLK 保持较高 |
| 效果 | B **不再复现** | A **消失**（目视稳定） |

**怎么证明是两个机理**：只修刷新 ⇒ B 好了、**A 还在**。**能被单变量实验切开，才叫两个机理。**

**被否证的优雅方案**：把 FMC 时钟源换成恒定的 PLL2R（这样 SDCLK 不随 CPU 变）——
实测**画面被读坏**（横向条纹/噪点，静态也坏）。原因是引入了 **AXI(HCLK) ↔ FMC_CLK 跨时钟域**，
两路同频不同相，而芯片**不开放该相位调节** ⇒ 这条路在原理上就是死的，不是没调好。

**顺带搞清的对照**：为什么同样变频，QSPI 没事而 SDRAM 出事？
**QSPI 是自同步**（控制器自生 SCK + 可配 dummy 周期，降频只增裕量）；
**SDRAM 是固定时序**（FMC 以 SDCLK 周期为单位写死延迟与刷新计数，只为一个频率标定）。

## 3. 存储：三条只有撞过才知道的物理约束

| 约束 | 现象 | 根因 | 修法 |
|---|---|---|---|
| **SD 的 DMA 中转缓冲落域** | FATFS 挂载后**首读必失败** | 缓冲放 D2 SRAM ⇒ 触发 AHB 错误 `IDMATE` | 落 **AXI 专用段 `.sd_dma_buf`**（32 B 对齐） |
| **SPI Flash 读必须一个 CS 窗口内完成** | 读回不稳，**低频反而更糟** | 一次读被拆成两条 HAL 传输，段间关闭传输在 CS 低电平时破坏了配置，命中 erratum 窗口 | 单 CS 窗口内**一次全双工** `TransmitReceive`，门控默认开 |
| **写后编程忙 / 迟到完成** | 偶发 `CMD_CRC_FAIL` / 通知超时 | 介质编程时间 + 超时后"救回"路径 | 按介质调 wait/重试策略；判据化而非硬编码超时 |

**另有一条"否证"值得讲**：ST 勘误 **ES0392 §2.8.3** 看着很像，但它前提是"多块读 + 使能读等待时钟停止"，
而实测寄存器三位全 0 且是**单块读 CMD17** ⇒ **不适用**。把真错误误判成"已知勘误"是最容易掉进去的坑。

## 4. 一份被三重证伪的栈深报告

| 缺陷 | 具体表现 |
|---|---|
| **把断言死亡路径当稳态** | `configASSERT` 的打印链单独就要 **1520 B**，`full` 口径下 11/11 个入口的最深路径都经过它 —— 但正常运行时不会走 |
| **分析死代码** | `fs_io_task` 在默认构建里**根本没被链接**（被 `--gc-sections` 回收），却被算出 828 B —— 甚至小于它自己的断言子树 |
| **函数指针不遍历** | 调用图在间接调用处停止（`.ci` 里 244 处只记占位）⇒ 对 LVGL / VFS 这类**表驱动派发**，静态值只是**下界** |

**触发点是一个物理上不可能的数**：报告说 GUI "最坏 1968 B"，而**实测高水位已用 7200 B**。
最坏值比实测小 ⇒ 不是某个数错，是**方法有系统性缺陷**。

**结论与改法**：对这类任务**静态上界不可得**；判据改为 **`full` / `noAssert` / `noALog` 三口径并列 + 实测高水位**，
并自建两个工具（objdump 独立重建调用图 + 指针多跳桥接）。同时把"**这份表不能用来缩栈**"正式写进文档。

## 5. 可靠性：能自愈的触摸总线

- **现象**：长时间运行 + 多次触摸后触摸失效，但触摸芯片的 INT 仍在翻转（芯片活着）。
- **取证**：gdb 读到 `SCL` 恒为 0、`I2C2 CR2` 残留未完成传输，而软件侧 `busy=0 / State=READY / 无 fault`
  ⇒ **软件状态全"正常"，是物理总线被从机拉死**。
- **修法**：定时器在空闲时检测 **SCL 连续拉低 ≥3×16 ms**（去抖）⇒ 任务上下文执行
  **bit-bang 打 9 个时钟 + STOP** + 外设 DeInit/ReInit + **DMA 重挂链** + 告警日志。
- **要点**：只写 `State = READY` 是**释放不了被物理拉低的总线**的 —— 这是"软件状态机"与"电气层"的边界。

## 6. 其它值得一提的小结论

| 主题 | 结论 |
|---|---|
| **堆** | 用 TLSF 经 `--wrap` 接管 `malloc/free`（含 newlib 重入版），池 = 整个 AXI SRAM；`tlsf_init` 必须在调度器启动后的任务里调（否则临界区嵌套哨兵值会遗留 `BASEPRI` 屏蔽，卡死 `HAL_Delay`） |
| **运行时间基准** | 不用 `DWT_CYCCNT`（480 MHz 下 **8.9 s 就回绕**），改用 **TIM2 @1 MHz**（挂在 APB1 外设时钟，WFI 不停）+ 溢出中断拼 64 位 + seqlock |
| **printf** | newlib-nano **不支持 `%llu`** ⇒ 64 位时间拆成 `sec.usec` 用两段 `%lu`；stdio 锁用 `retarget_lock` 覆盖 |
| **链接** | 曾为"能链接过"加全局 `-Wl,--allow-multiple-definition`，结果**静默吞掉重复的 HAL 回调**（传感器全挂且零报错）⇒ 改用 `--wrap` 精确豁免 |
| **日志** | 分级（全局/串口/文件）+ tag 过滤；**tag 槽位不够会静默丢日志**（"日志里没有"≠"代码没执行"） |
| **调试器** | `DBGMCU_CR` 曾被写成 IDCODE 只读值 ⇒ `DBG_SLEEP` 从未生效，idle WFI 门控内核时钟导致 SWD 掉线 |
